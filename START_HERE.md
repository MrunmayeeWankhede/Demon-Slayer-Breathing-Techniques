# Breathing Studio

Your TouchDesigner breathing-style interface, with an automatic project builder.

This version builds the network for you. You do not need to create operators, paste shaders, or wire parameters by hand.

## 1. Open the interface

Install and open the current **Official TouchDesigner** for Windows or macOS. Non-Commercial works for a personal learning project. [Download TouchDesigner](https://derivative.ca/download).

In TouchDesigner, open **Dialogs → Textport**. Paste this line, press Enter, and select **`INSTALL_IN_TOUCHDESIGNER.py`** from this folder:

```python
p = ui.chooseFile(); exec(compile(open(p, encoding='utf-8').read(), p, 'exec')) if p else None
```

The installer creates a `BreathingStudio` component and opens its interface window. It embeds the shader and controller text, so the resulting TouchDesigner project does not rely on external shader paths.

**Try it immediately:** move your mouse inside the large stage, click a style, and use the Pinch / Open Palm / Fist buttons. This is explicitly labeled **MOUSE DEMO**. When your mouse leaves the stage, the demonstration moves on its own.

Click **Save project** to save a `.toe` wherever you want. The installer itself is Python source, not a prebuilt `.toe`. The complete project is generated by your installed copy of TouchDesigner. It does not delete your existing project nodes. Running it again opens the existing completed component.

## 2. Turn on your camera and voice

You need Python **3.11 or 3.12**, preferably the installer from [python.org](https://www.python.org/downloads/) with Tk support. On Windows, include the Python launcher. This is a separate interpreter from TouchDesigner's internal Python.

- **Windows:** double-click `START_WINDOWS.cmd`.
- **Mac:** open `START_MAC.command`. If it does not open as a terminal script, open Terminal, type `bash `, drag that `.command` file into Terminal, then press Enter.

In the controller window, click **Install / Start controller**. The first run creates a private Python environment, installs the packages, and downloads the hand and voice models. Let it finish; this can take several minutes. Future runs reuse that installation. Keep this extracted folder in the same location afterward.

Each start tests hand inference before requesting the camera or microphone. Look for **Hand tracker self-test PASSED**. The Mac compatibility build uses the CPU Hands pipeline and fixed versions of its core packages. Replacing `requirements.txt` automatically triggers the package update on the next start.

Allow camera and microphone access if your operating system asks. A small camera preview appears; TouchDesigner switches to live input when the controller connects. If you intentionally selected Mouse demo, click **Camera + voice** to switch back.

Show your controlling hand. The preview writes a **Right** or **Left** label beside it. If your intended hand has the opposite label from the launcher's selection, stop the controller, change the label in the launcher, and start again.

If your webcam is busy, close Zoom/FaceTime/other camera apps. Camera index `0` and a blank microphone index use the default devices. Use **List microphones** to see input-device indexes if needed. You can turn voice off with the checkbox and still control styles using the TouchDesigner buttons.

## 3. Perform

| Do this | Result |
|---|---|
| Say fire or flame, water, mist, stone, love, wind, serpent, insect, or sound | Select that style |
| Pinch thumb and index, keeping other fingers extended | Assigned variation 1 |
| Show an open palm | Assigned variation 2 |
| Make a fist | Assigned variation 3 |
| Move your hand | Move the emitter and draw its trail |
| Move faster | Increase visual intensity |
| Show the other hand and spread hands apart | Increase the radius of applicable effects |
| Say stop / start, or use Pause / Resume | Pause / resume emission |
| Click Trails | Turn trails on or off |

Say one style clearly and pause briefly. “Water breathing” also works. Voice switches on finalized recognized phrases, so it is slower than hand movement. “Fire” selects Flame; this build does not have a separate Sun Breathing style.

The live form follows your pose, so the three form buttons are disabled in live mode. Click a different style any time; the next accepted spoken style command takes over. The camera preview also accepts keys **1–9** for styles, **Space** to pause, and **Q** to quit, when that preview has keyboard focus.

For example, Water's three assigned forms are **Water Surface Slash**, **Water Wheel**, and **Dead Calm**. There are 27 named variations across nine styles. The hand gestures are custom interface controls; they are not canonical anime hand signs. The visuals are stylized procedural interpretations, not imported anime footage or exact reproductions.

## What is already built

- Nine style buttons, with the selected style highlighted.
- Dynamic style and form titles.
- A mouse demo with three selectable forms.
- Live camera/voice input, handedness selection, and device settings.
- Hand-position smoothing, stabilized poses, pinch hysteresis, and capped movement intensity.
- Trails and soft glow, with no text ghosting.
- Two-hand radius control and a connecting string in the appropriate Sound variation.
- Pause, resume, controller disconnect timeout, and sender restart handling.
- Local dependency/model installation and a visible diagnostic log.
- A button that saves the generated TouchDesigner project as `.toe`.

The base interface has effects on a dark background. To show yourself with the effects in a clean recording window, run the included `ADD_CAMERA_VIEW.py` inside your working TouchDesigner project; see `CAMERA_VIEW.md`. Only one hand selects a form; the other changes size. This build does not yet recognize full sword-like movement choreography or render a tracked 3D sword.

## If something does not work

| Problem | Action |
|---|---|
| Installer shows a missing parameter error | Use current Official TouchDesigner. The error names the node/parameter. The partial component is retained for diagnosis; rename it before rerunning. |
| A red/checkerboard shader appears | Inside `BreathingStudio`, open `effect_compile` or `finish_compile` to read the actual shader error. |
| The interface window is closed | Run the installer again, or pulse Open as Separate Window on its `display` Window COMP. |
| Effects stop in live mode | Check controlling-hand label, visible pose, and pause state. The UI says when it is waiting for the controller. |
| Voice does not work | Check the controller log and mic permissions/index; leave voice unchecked to use hand tracking and style buttons meanwhile. |
| Mac crashes with `DrishtiMetalHelper` / `Service is unavailable` | Apply the Mac compatibility patch: replace `bridge.py`, `launcher.py`, and `requirements.txt` in the existing folder, then click Install / Start controller. The patch switches Mac hand inference to the CPU Hands pipeline. If the startup test fails, copy its log; that test does not use device permissions. |
| An older launcher reports `CERTIFICATE_VERIFY_FAILED` while downloading a model | Replace `launcher.py` with the corrected version. It uses the trusted certifi bundle from the project environment while keeping HTTPS certificate verification enabled. |
| Windows/Mac launcher cannot find Python | Install Python 3.11 or 3.12 from python.org; reopen the launcher. |
| Form recognition is unstable | Face your palm toward the camera, improve lighting, and keep hands from overlapping. |
| Your old controller does nothing | This version uses an extended state packet. Close the earlier starter's controller and use this folder's launcher. |
| FPS is low | Turn trails off. Reduce the `Intensity` parameter only for brightness; it does not improve FPS. Lower the effect/finish TOP resolution for actual GPU savings. |

This package was built in Linux without TouchDesigner. Both shaders passed standalone GLSL-to-SPIR-V compilation with TouchDesigner compatibility declarations. The speech model loaded and decoded silent test audio. The full TouchDesigner builder, visual layout, live hand inference, and physical microphone/camera integration could not be executed here. The patched CPU tracker passed blank-frame inference in Linux, but this does not test real hands or Mac/Windows capture. Those checks remain for the machine running the project. See `VALIDATION.md` for the exact limits.

## Files

`INSTALL_IN_TOUCHDESIGNER.py` is self-contained and can build the demo without the other files. `launcher.py`, `bridge.py`, `requirements.txt`, and `model-checksums.json` must stay together for live control. `source/` contains readable project-builder and shader sources for editing. The launcher creates `.venv/`, `models/`, `controller-settings.json`, and `controller.log` locally when used.

The only intentional downloads are Python packages and the two public models. During normal operation the controller processes video/audio locally, sends control values to `127.0.0.1:9000`, and serves its latest clean camera frame at `127.0.0.1:9001/frame` for the optional camera-view add-on. It does not record camera video or microphone audio; the log includes recognized command text and diagnostic messages.
